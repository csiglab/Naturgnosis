# Philosophia Representationis Comparativae et Operis

> Reality is the total set of phenomena, entities, and processes that exist or occur, independently of an observer's perception or conceptualization, and which can, in principle, interact, change, or produce effects.

> Philosophia Representationis Comparativae is the scaffolding used to represent instances so that they can be compared — placing every case on the same dimensional grid, with the same elements, values, and mapping rules, so that two instances can be compared dimension by dimension.

> This note systematizes the framework that renders instances comparable across diverse domains. It is the complement of Philosophia Artium Epistemicarum et Operis (which systematizes intelligibility), Philosophia Artium Technicarum et Operis (which systematizes intervention), Philosophia Socialium et Operis (which systematizes association), and Philosophia Conceptuum et Operis (which systematizes concepts): where those notes ask how reality is known, transformed, coordinated, and conceptualized, this one asks how cases are represented so that they can be compared.

## Formulation

### What is a `Comparactive Representation`?

> A **Comparactive Representation** is a rule-governed description of an instance that states how that instance stands with respect to a fixed set of Characteristic Elements. The term has two related senses.

> In the **logical-mathematical sense**, a characterization of an object or class is a set of conditions that is necessary and sufficient for it: the object satisfies the conditions, and whatever satisfies them is (or is equivalent to) the object or class. It answers the question: *what must hold for X to be X, and what follows if it does?* A characterization in this sense need not single out exactly one object; it may characterize a class, a structure, or a property. When it does single out exactly one object, it is a **unique characterization**.

> In the **comparative-system sense** used in this note, a **Comparactive Representation** is the structured profile produced when a Comparactive Representation System assigns a value to each Characteristic Element for a given instance. It answers the question: *how is this instance placed on the same dimensional grid as every other instance?* Its function is comparability, not identification. Many instances may share the same Comparative Profile; that is not a defect, because the purpose is to compare, not to single out.

> Formally, under a Comparactive Representation System `S`, the Comparactive Representation of an instance `i` is the tuple:

> `C_S(i) = ⟨v_1, v_2, ..., v_n⟩`

> where each `v_k` is the value assigned to `i` by the mapping rule for Characteristic Element `k`. Two instances are directly comparable only when characterized under the same version of `S`. The Comparactive Representation need not be unique to `i`; its purpose is to render `i` comparable along the dimensions that `S` fixes.

> **Example.** In the logical sense, “having three sides” characterizes a triangle. In the comparative-system sense, an agency might be characterized as `⟨jurisdiction: national; function: regulatory; autonomy: high; legal form: statutory authority⟩`. The first picks out a class by necessary and sufficient conditions; the second places one instance on a multi-dimensional comparative grid.

### What is a `Comparactive Representation System`?

> A **Comparactive Representation System** is a finite, reusable apparatus for assigning each instance within a defined universe a comparable profile. It consists of a fixed set of **Characteristic Elements**, each with a closed set of possible values, and explicit **mapping rules** that determine which value applies to each Characteristic Element for a given instance.

> A **characterization** describes a single instance using a set of Characteristic Elements and their corresponding values. A **Comparactive Representation System** generalizes this process to an entire population, assigning each instance a value for every Characteristic Element and thereby enabling systematic, dimension-by-dimension comparison. Any change to the set of Characteristic Elements or their possible values creates a new version of the system. Consequently, instances are directly comparable only when characterized under the same version of the system.

### What is the general form of a Comparactive Representation System?

| Component | Description |
|---|---|
| **Characteristic Element** | A defined aspect of an object along which it is characterized. |
| **Value Set** | The set of possible values that the Characteristic Element can take. |
| **Value Assignment Rule** | The rule or procedure used to determine the value of a Characteristic Element for a given object. |
| **Comparative Profile** | The collection of values assigned to an object across the Characteristic Elements. |

## How to build a Comparactive Representation System?

### How is a Characteristic element derived?

> The decomposition workflow, in order. Each step constrains the next; skipping a step pushes its cost into the comparison phase, where it is paid once per case instead of once per system.

1. **Fix the instance class.** State what counts as one instance (one agency, one program, one artifact) and what is out of scope. A system that cannot say what it profiles cannot be validated.
2. **Choose the approach.** Element inventory, type assignment, dimensional profile, model derivation, or a deliberate combination. The approach determines what the profile looks like.
3. **Fix the dimensions.** One question per dimension, independent of the others. Fewer, sharper dimensions beat many overlapping ones; every overlap is double-counted variation.
4. **Close the categories.** Mutually exclusive, jointly covering, with concrete membership tests. Write the mapping rule for each category before characterizing the first case.
5. **Characterize a pilot sample.** Three to five diverse cases, characterized independently by two analysts. Disagreements rewrite the rules, not the cases.
6. **Test portability.** Apply the system to the most distant case in the intended sample (another jurisdiction, another period). If it forces or overflows, revise dimensions or categories and re-version.
7. **Freeze and version.** Record the version with the comparison. Every later change — a dimension, a category, a rule — creates a new version.

### What Concrete Methods or Strategies Can Be Used to Derive a Characteristic Element?

> **A Framework for Building a Comparactive Representation System is a standalone, structured set of concepts, principles, models, and methods that provides a basis for designing and developing a system for characterizing a particular domain.**

| **Concrete Method * Strategy** | Description | How Does It Help Derive Characteristic Elements? |
|---|---|---|
| **Ontological Analysis** | Identifies the entities, properties, relations, structures, and processes that constitute the domain. | Identifies domain-grounded aspects that can serve as candidates for Characteristic Elements. |
| **Domain Analysis** | Investigates the boundaries, composition, diversity, and organization of the domain. | Identifies which aspects of the domain need to be represented and where meaningful differences between objects arise. |
| **Object Decomposition** | Decomposes objects into their constituent elements, properties, functions, and relationships. | Identifies candidate elements from the internal composition and organization of the objects. |
| **Property Analysis** | Examines the properties of objects, including their types, dependencies, and variations. | Identifies properties that can be represented directly or used to formulate more abstract Characteristic Elements. |
| **Relational Analysis** | Examines relationships between objects and between their constituent elements. | Identifies relational Characteristic Elements, such as an organization's relationship with a ministry. |
| **Functional Analysis** | Examines the functions and activities performed by objects. | Identifies functional Characteristic Elements, such as the functions an organization is authorized or expected to perform. |
| **Comparative Analysis** | Compares instances to identify similarities and differences. | Reveals variations that may justify introducing Characteristic Elements. |
| **Conceptual Analysis** | Examines the meaning, scope, assumptions, and relationships of concepts used to understand the domain. | Clarifies candidate elements and establishes the conceptual distinctions they are intended to represent. |
| **(Conceptual) Composite Model Approach** | Characterizes an object through a set of interconnected submodels, each representing a distinct aspect of the object. The submodels jointly form the complete Comparactive Representation model. | Allows Characteristic Elements to be derived within separate submodels, each addressing a particular aspect of the domain, and then integrated into a unified Comparactive Representation System. |
| **Purpose-Driven Analysis** | Starts from the questions, decisions, and analytical tasks the Comparactive Representation System must support. | Identifies which aspects of objects must be represented to serve the system's intended purposes. |
| **Existing Classification Analysis** | Examines established taxonomies, classification schemes, and typologies relevant to the domain. | Identifies existing distinctions and candidate elements while revealing gaps, ambiguities, and incompatible classifications. |
| **Literature-Based Derivation** | Examines relevant academic and technical literature to identify established concepts, variables, attributes, and distinctions. | Provides theoretically grounded candidates for Characteristic Elements and clarifies their established meanings. |
| **Expert Elicitation** | Uses structured interviews, workshops, or other techniques to obtain knowledge from domain experts. | Reveals relevant aspects and distinctions that may be undocumented or difficult to identify through other methods. |
| **Empirical Observation** | Examines actual instances through observation, documents, records, and other evidence. | Identifies observable properties and recurring patterns that can ground candidate Characteristic Elements. |
| **Case-Based Analysis** | Investigates selected cases in depth, including typical, atypical, and boundary cases. | Reveals overlooked properties and distinctions and tests whether candidate elements adequately represent actual instances. |
| **Inductive Generalization** | Derives general concepts or patterns from multiple observed instances. | Produces candidate elements from recurring properties and distinctions across instances. |
| **Deductive Derivation** | Derives implications from an existing theory, conceptual model, or set of principles. | Identifies Characteristic Elements implied by an established theoretical account of the domain. |
| **Abstraction** | Selects and generalizes relevant features while disregarding details unnecessary for the intended representation. | Transforms concrete observations and properties into more general Characteristic Elements. |
| **Construct Development** | Develops abstract concepts to represent phenomena that cannot be adequately captured by a single directly observable property. | Produces elements representing theoretical constructs, such as institutional autonomy or organizational complexity. |


### When does decomposition become fragmentation?

> Too much decomposition creates fragmentation: elements so fine that every case is unique and no comparison survives. The stopping rule is comparability — decompose until cases differ informatively, then stop. One can introduce an interface that pools several underlying elements for interaction purposes, but the Comparactive Representation System records the level at which comparison still works, never the finest level that can be observed.


## (Evaluation) How Can the Quality and Adequacy of a Comparactive Representation System Be Evaluated?

>  The quality and adequacy of a **Comparactive Representation System** can be evaluated against the following general criteria:

| **Criterion** | **Description** |
|---|---|
| **Descriptive Coverage** | Can the system capture the relevant characteristics of the instances within its defined universe? |
| **Comparability** | Does the system enable meaningful comparisons between instances using a common set of Characteristic Elements and rules? |
| **Discriminative Power** | Can the system distinguish instances that differ in relevant respects? |
| **Classification Adequacy** | Can the system classify instances into meaningful types using explicit and consistent criteria? |
| **Descriptive Precision** | Can the system characterize individual instances with sufficient specificity and detail? |
| **Conceptual Clarity** | Are the concepts, definitions, and distinctions used by the system clear and unambiguous? |
| **Internal Consistency** | Are the system's concepts, dimensions, categories, values, and mapping rules logically consistent? |
| **Ontological Coverage** | Can the system accommodate the relevant diversity of entities, forms, and configurations within its defined universe? |
| **Representational Fidelity** | Do the system's Comparactive Representations adequately correspond to the actual characteristics of the instances being represented? |
| **Analytical Utility** | Does the system support meaningful analysis of instances, their characteristics, and the relationships between them? |
| **Explanatory Capacity** | Does the system help explain relevant differences, structures, and configurations rather than merely describe them? |
| **Operational Applicability** | Can the system be applied consistently to real-world instances using available evidence and feasible procedures? |
| **Reproducibility** | Can different users apply the system to the same instance and obtain sufficiently consistent Comparactive Representations? |
| **Adaptability** | Can the system accommodate changes in its universe, including new forms, configurations, and emerging characteristics? |
| **Parsimony** | Does the system capture the necessary distinctions without introducing unnecessary complexity, redundancy, or excessive granularity? |
| **Information Preservation** | Does the system preserve the information necessary for its intended analytical purposes without excessive loss through abstraction? |
| **Extensibility** | Can the system incorporate additional dimensions, categories, values, and mapping rules without requiring fundamental reconstruction? |
| **Purpose Adequacy** | Does the system provide the characteristics, distinctions, and information necessary to fulfill its intended objectives? |

## QA

### What a Comparactive Representation System is not?

- **Not a taxonomy**: a taxonomy classifies by shared properties into a tree; a Comparactive Representation System profiles across several independent dimensions at once. See the [Taxonomia](/glossarium/?t=taxonomia) term.
- **Not a model**: a model explains or predicts; a Comparactive Representation System describes and compares. A model can generate the dimensions of a system, but the system itself carries no causal claims. See the [Model](/glossarium/?t=model) term.
- **Not a definition**: a definition fixes the boundaries of one term; a system fixes the comparison space of many instances. See the [Definir](/glossarium/?t=definir) term.

### Which are the set of specific epistemic methods?

> Comparactive Representation is one epistemic method among several. Each related method answers a different question; together they cover the path from raw reality to comparable representation.

| Method | Description | Relation |
|---|---|---|
| **Decomposition-tree method** | Recursively decomposes an instance into constituent elements through explicitly typed parent–child links until every leaf resolves to an instance. | Supplies the parts from which Characteristic Elements are derived; governed by the social, technical, epistemic, and natural philosophiae. See [Philosophia Socialium et Operis](note.html?n=meta/philosophia-socialium-et-operis.md). |
| **Concept evaluation** | Assesses whether a concept is fit for its analytical purpose: identity, coherence, coverage, economy, epistemic performance, and validity. | Validates the concepts used as Characteristic Elements before they enter a system. See [Philosophia Conceptuum et Operis](note.html?n=meta/philosophia-conceptuum-et-operis.md). |
| **Taxonomy and typology** | Classifies instances into kinds by shared properties. | Provides candidate types and classes; a Comparactive Representation System profiles across dimensions where a taxonomy branches a tree. See the [Taxonomia](/glossarium/?t=taxonomia) term. |
| **Modeling** | Builds simplified representations that explain or predict. | Generates the dimensions of model-based characterization; the system itself carries no causal claims. See the [Model](/glossarium/?t=model) term. |
| **Measurement and indicators** | Translates elements into observable, repeatable procedures. | Operationalizes mapping rules so independent analysts reach consistent Comparactive Representations. |
