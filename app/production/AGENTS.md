# AGENTS.md — Production Space (derived view)

## Purpose

Coarse-grained view of the production sphere — **not a dataset**. Its nodes live in Social
Space, marked with the reserved `production-view` tag when they play a production role
(products, firms, markets, processes, capabilities); the view graph is computed by
`bin/build_production_view.py`. Spec: `spec/production/README.md`. Fine-grained technique
belongs to `app/technique/` — keep the boundary. Market analysis lives here only as a view;
market nodes are owned by Social Space.

## Layout

- `web/index.html` — explorer over `../data/view.json` (+ `view-layout.json`); no editor
  (nodes are created/edited in `/social/`, which owns them).
- `data/view.json` + `data/view-layout.json` — generated by `make production-view`;
  never edit by hand (recompute instead). No `data.json`/`layout.json` here on purpose:
  their presence would make `sync.py` treat production as an editable dataset.
- `data/schema/` — JSON Schema + notes (kept for the explorer's vocabulary).

## Commands

```sh
make production-view                  # recompute view.json + view-layout.json (commit both)
python bin/sync.py --no-couch         # static smoke test: /production/ → 200
```

## Invariants

- There is no `production` dataset: no CouchDB docs, no `data.json`, no editor. Never
  re-create any of the three; `seed_couchdb.py` and the API must stay production-free.
- New production content is added as Social nodes carrying the exact tag
  `production-view` (see "Derived views" in `guideline/README.md`), then
  `make production-view` regenerates the graph. Only edges with both ends in the view
  are kept.
- Keep `web/index.html`'s data-loading contract (`view.json` shape `{nodes: [...]}`)
  in sync if the builder output changes.
