What Naturgnosis Is

Naturgnosis identifies and formalizes the set of epistemic elements that enable an agent to effectively navigate — understanding and action — reality, especially social reality. It is the main index of the world's technique and episteme: a comprehensive, structured, navigable registry of the world epistemic and technical practice.

Its product is a Domain Epistemic Artifact Set (DESA) per space — nodes are the elements the theory distinguishes, edges are the typed relationships that make a domain intelligible, and every artifact links back to real-world actions, interventions, and decisions.

Epistecnica is the sibling project: what is intentionally pursued through deep study and mastery. The two are kept separate — nothing leaks between them without explicit intent.

The Theory

Technique and operation

Philosophia Artium Technicarum et Operis systematizes purposeful (agentic) operation and its primary driver: technique, the organized method for achieving a desired transformation through purposeful action. Its most abstract formulation of operation:

  • Requirements → Technique → Product (good, service).
  • Desired Difference → Controlled Transformation → Realized Difference.

Technique content is decomposed per its "How to decompose any technical instance?" workflow — root, typed intermediates, instance leaves, recursion — with one tree per element type when an instance reads multiply (multi-root forest, never two types on one row).

The epistemic arts

Philosophia Artium Epistemicarum et Operis is its counterpart: how reality becomes intelligible. Ontology and epistemology are mutually constraining duals of the same epistemic act — ontology constrains what is, epistemology how the known is accessed and represented. Both guides live as meta notes in the corpus (technicarum, epistemicarum) and are binding for decomposition work.

The Spaces

Social Space — the main module

The ontic–agentic–epistemic elements rendering social reality intelligible: actors, institutions, roles, norms, beliefs, relationships — — nodes. Explore it in the explorer and edit it in the editor.

Production Space

The production sphere: techniques, products, firms, processes and the capabilities binding them — — nodes. Explorer · editor.

Research Space

The world's research apparatus: institutes, laboratories, funding agencies, universities — — nodes. Explorer · editor.

Nation Space

A structured registry of sovereign systems in the Index Gentium grammar: per-nation entries with vital statistics — — nations. Index · editor.

Technique Space

Fine-grained technique beneath the production layer: artifacts, engineering principles, methods — — nodes. Explorer · editor.

Epistemic Space

The set of elements that renders reality intelligible: disciplines, fields, and bodies of knowledge — — nodes. Explorer · editor.

Nature Space

The ontic counterpart to Epistemic Space: physical and living phenomena existing independently of inquiry — — nodes, seeded with the ontic elements moved out of epistemica. Explorer · editor.

Note Space & Universal Index

Long-form notes live in the catalog (— notes, plain markdown plus a generated index). The universal index (Graphive) renders every graph space on one read-only canvas; universal search in the hub header covers all of it via make search-index, deep-linking into explorers with ?node=<id>.

Architecture, for the Curious

One small server (bin/sync.py) fronts every module from a single image. Graph data lives in CouchDB (one document per node, ids namespaced {dataset}:{node_id}), mirrored to app/<module>/data/data.json on every save so the read-only viewers keep working off static files. CouchDB is a persistent dependency of the environment — workflows connect to it, never provision it.

EndpointPurpose
GET /api/healthService + CouchDB status
GET /api/graph?dataset=…Nodes for a dataset
POST /api/graph/saveEditor upsert/delete + mirror
POST /api/layout/recompute?dataset=…Regenerate layout.json
GET/POST /note/api/pinsNotes-catalog pins (read / toggle)

Deliberate rebuilds, committed like code: make build (notes + search + universal + layouts), make universal-index, make seed (push mirrors into CouchDB). In offline mode (--no-couch) the API answers 503 and the static mirrors carry the pages.

Design

Every surface derives from the Oxford Common Room tokens (app/shared/theme.css); colors are never hardcoded. Module directory = URL segment = dataset id; fixed data names inside a module (data.json, layout.json, index.json, schema.json). Conventions live in guideline.md and bind contributors and agents alike.
