# Q/A Log Space

> Static, searchable log of agent interrogations: the questions agents
> worked through, with answers where resolved.

## Status: bootstrapped

Seeded with `qa-00001` (chemical elements — material forms: isolated vs.
incorporated into compounds, minerals, rocks, fluids, biological matter).

## Storage model

- **Source of truth: `app/qa/data/qa.json`.** A hand-normalized JSON array,
  one object per entry:
  `id, question, answer, agent, run, date, source, tags, status`.
  Ids are `qa-%05d`, stable, never reused.
- **Derived: `app/qa/data/qa-index.json`**, generated by
  `bin/build_qa_index.py` (id, title, agent, run, date, tags, excerpt,
  lowercased full text, word count). Committed so the catalog works without
  any backend; rebuild and commit after editing `qa.json`.
- **Raw drops** live in `app/qa/import/` (archival, never hand-edited).
- **Not a graph dataset.** No `data/data.json`, no CouchDB docs, no editor.
  `bin/sync.py` serves it statically (`/qa/` → `/qa/web/`).

## UI

- **Catalog** `app/qa/web/index.html` — stats, full-text search, agent/run
  facets, tag chips (`?tag=`), pagination; loads `../data/qa-index.json`.
- **Entry** `app/qa/web/entry.html?id=<qa-id>` — question, answer (or
  `awaiting answer`), meta, prev/next, back to catalog.

## Operations

```sh
python bin/build_qa_index.py     # rebuild the index after editing qa.json
python bin/build_search_index.py # rebuild the hub universal index
```

## Conventions

- English preferred; keep original-language terms in the body.
- Tags are kebab-case (`chemical-elements`), same rule as notes.
- `status` is `open | answered | deferred`.
