# Note Space

> Long-form notes for Naturgnosis rendered as a searchable catalog: plain
> markdown with zero required metadata, indexed and served.

## Status: bootstrapped

Viewer machinery ported from Epistecnica's note system (code only — none
of its personal notes). The corpus lives in `app/note/data/` in topic-first
sections (`social/` social-ontology concepts and social actors
under `social/actor/` (firms, banks, ministries, plus people under
`social/actor/persona/`), `technique/` tools/systems/libraries/platforms/instances
(plus housekeeping under `technique/operation/`), `live/` interactive pages by topic,
`meta/` task guides); see `authoring.md` for the authoring rules.

## Storage model

- **Source of truth: physical markdown.** One file per note under
  `app/note/data/` (`<section>/<kebab-case>.md`); top-level directory is
  the section. The generated `index.json` sits beside the corpus and is
  never hand-edited. Self-contained hand-authored HTML pages (`*.html`) are
  **live notes**: served as-is with a `live` chip, never rendered through
  the viewer, no CDN libraries allowed.
- **Derived:** `app/note/data/index.json`, generated by
  `bin/build_note_index.py` (path, title, section, kind, tags, headings,
  text, word count). The index is committed so the catalog works without
  any backend; rebuild and commit it after adding or renaming notes.
  The notes index also feeds the hub universal search
  (`bin/build_search_index.py` → `app/data/search-index.json`).
- **Pins are server-side**, not per-browser: `GET/POST /note/api/pins`
  (see `bin/sync.py`) reads and upserts a single `pins` doc in the
  `naturgnosis` CouchDB database. The server validates paths against the
  corpus naming rules; the catalog hides the pin UI when the API is
  unreachable and filters out pins whose notes no longer exist.
- **Not a graph dataset.** The note module carries no `data/data.json`,
  needs no CouchDB dataset, and is invisible to seeding/layout tooling.

## UI

- **Catalog** `app/note/web/index.html` — file-explorer card grid in two
  modes (`?view=browse|files`, default `browse`; legacy `dirs`/`tree`
  resolve to `browse`): browse mixes folder cards (gold folder glyph,
  note counts) with direct file cards in the current directory, files is
  the flat list of every file; file cards carry an inline-SVG file glyph
  (amber for live notes), title, and path. Clicking folders, breadcrumb
  ancestors, or `× all notes` navigates in place via `pushState` (browser
  Back works; links stay shareable); the breadcrumb always shows which
  directory is open. Full-text search (`?q=` deep link, prefilled) scopes
  to the directory; no section/tag facet UI — filtering is search plus
  the pinned toggle only. Pins are fully kept: card pin buttons, the
  `★ pinned` viewbar toggle, `?section=pinned` deep link, and the
  server-side pins API. Stats behind a button (`stats` modal:
  notes/sections/words plus per-section table); fixed 48-cards pagination;
  loads `../data/index.json`, pins from `/note/api/pins`. Viewer tag chips
  link to `?view=files&q=<tag>`; the treemap links sections to
  `?view=browse&dir=<section>` (tag drill-down appends `&q=<tag>`).
- **Viewer** `app/note/web/note.html?n=<path>` — fetches `../data/<path>`,
  renders markdown via vendored `marked`, table of contents, word count and
  read time, tag chips (from `--- tags: [...]` front matter, stripped
  before render), raw-file link, breadcrumb back to the catalog (root
  `notes` plus every intermediate directory linking to its `?dir=` listing).
  Rejects non-kebab paths client-side (mirrors the server validation).

## Operations

```sh
python bin/build_note_index.py     # rebuild the index after editing notes
python bin/build_search_index.py   # rebuild the hub universal index (needs notes-index first)
```

## Conventions

- File name = slug (ASCII lowercase, `-` separated); the human title lives
  inside the file (first `# ` heading), never in the file name. Canonical
  slug: NFKD to ASCII, lowercase, runs of non-alphanumerics to `-`
  (`bin/build_note_index.py:slugify_segment()`, Epistecnica parity);
  the builder suggests the normalized form in its warnings.
- Optional tags in `---` front matter (`tags: [kebab-tag, …]`); invalid
  tags warn and are dropped. Tags power catalog facets and viewer chips.
- English preferred; keep original-language terms as aliases in the body.

## Non-goals

- No live notes ship yet (machinery supports them when authored here).
- No Epistecnica content, brand, or tokens — verified by grep (see
  verification notes in the porting change set).
- No note→graph jumps yet (deferred **entity → view** idea: a note
  front-matter node reference rendered as a "view in graph" chip —
  needs a note↔node id mapping that does not exist yet). Universal
  search already deep-links *node* hits to `?node=` in the explorers.
